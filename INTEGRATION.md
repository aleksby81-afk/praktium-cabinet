# ПРАКТИУМ: связь магазина и кабинета

Основной сайт: https://aleksby81-afk.github.io/Praktium_magazin/

Кабинет оформлен в цветах магазина и содержит семь его товарных позиций. Сайт пока является отдельным статическим прототипом: форма и корзина на нём не отправляют данные. Поэтому заявки, созданные на основном сайте, **не появляются автоматически** в кабинете. Покупателю следует оформлять заявку непосредственно в кабинете; там она сохранится и будет видна по статусу.

В публичном каталоге магазина цены не указаны. Семь товаров в `backend/app/seed.py` создаются с технической ценой `0.00`, которую интерфейс показывает как «Цена уточняется», без ложного обещания бесплатного товара. Перед переводом заявки в `done` администратор должен указать согласованную цену через `PATCH /admin/orders/{id}/price` с телом `{"unit_price":"2500.00"}`. После этого на финальном статусе начисляется кэшбэк. Цены товара для новых заявок можно указать при создании каталога через Admin API.

## Как подключить основной сайт

1. Разверните backend и frontend кабинета по `README.md`. Запуск одного HTML-файла не создаёт доступный покупателям сервис: для регистрации, заявок и статусов нужен работающий backend и база данных.
2. В frontend укажите публичный адрес backend в `VITE_API_URL` перед сборкой. В backend разрешите точный origin кабинета в `CORS_ORIGINS`.
3. После появления публичного HTTPS-адреса кабинета добавьте на основной сайт ссылку «Личный кабинет» в шапку и рядом с формой заказа. Пример:

   ```html
   <a href="https://АДРЕС-КАБИНЕТА/login">Личный кабинет</a>
   ```

4. В тексте у формы основного сайта предложите покупателю перейти в кабинет, если он хочет сохранить заявку и видеть её статус. Для автоматического переноса форм и корзины потребуется отдельная интеграция с API и согласование потока данных.
5. Проверьте регистрацию, создание заявки и переходы по статусам на публичных адресах. Сайт GitHub Pages нельзя направить на локальный `localhost` пользователя.

Пока публичный адрес кабинета неизвестен, ссылка на него не добавлена в работающий магазин. Кабинет сам содержит ссылку на основной сайт. Фотографии товаров находятся внутри HTML основного сайта как встроенные данные; кабинет показывает нейтральные иллюстрации категорий, пока фотографии не будут размещены отдельными файлами и переданы как `image_url` через Admin API.
